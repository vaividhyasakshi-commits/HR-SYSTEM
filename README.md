# UMNNI HR Daily Work Reports — React + Gmail

React/Vite dashboard + Node/Express Gmail read-only API. Demo data is included; **no office emails or passwords are included**.

## VS Code: run locally

1. Install Node.js 20+ and open this folder in VS Code.
2. Open VS Code Terminal and run:

   ```bash
   npm install
   cp .env.example .env
   npm run dev
   ```

   On Windows PowerShell, use `Copy-Item .env.example .env` instead of `cp`.
3. Open **http://localhost:5173**. The backend runs at port 3001. Local demo login: username `hradmin`, password `UMNNI@Demo2026!`. Without Gmail credentials, the UI shows demo status.

## What UMNNI needs to provide

- Employee register: **17 submitted email addresses**, mapped to four teams in `data/employees.json` (Graphic Design 4, Video Editing 9, Web Development 2, Sales 2). Display names are provisional guesses from email addresses; confirm spellings before production. Keep sender emails unique.
- Gmail / Google Workspace admin or authorized mailbox owner must approve access to `info@umnni.com`. Confirm that this is the actual Google mailbox, not merely a forwarding alias.
- One agreed **dated subject** format: `Daily Work Report - DD/MM/YYYY` (e.g. `Daily Work Report - 29/10/2026`). `REPORT_SUBJECT` is the `Daily Work Report` prefix. Matching ignores capitalization and extra spaces around the dash, but the date must match the selected day.
- A Google Cloud project with **Gmail API enabled**, OAuth consent configured, and OAuth client credentials. Authorize with the **gmail.readonly** scope using the mailbox owner’s account, and securely obtain a refresh token for the backend. Google may require app verification/admin policy approval depending on organization and consent setup.
- HR-only access policy, private `HR_USERNAME` and strong `HR_PASSWORD`, HTTPS hosting for production and a server/platform to run Node. Do not expose credentials in browser code or commit `.env`. The provided demo password works only in local development.

## Activate real Gmail data

Set these server-side values in `.env`:

```ini
MAILBOX_EMAIL=info@umnni.com
REPORT_SUBJECT=Daily Work Report
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
GOOGLE_REFRESH_TOKEN=...
HR_USERNAME=...
HR_PASSWORD=...
```

The refresh token must be generated by the mailbox owner through Google's authorized OAuth 2.0 consent flow using `https://www.googleapis.com/auth/gmail.readonly`, with offline access. **Never send tokens or passwords over chat.** Store secrets in your host's protected environment variables. The API rejects non-registered sender emails, unrelated subjects, wrong recipients, and messages outside the selected date in Asia/Kolkata. It returns the latest matching email per employee per day. Inbox emails are never modified or deleted. The dashboard refreshes every 60 seconds.

## Build and serve

```bash
npm run build
npm start
```

Open `http://localhost:3001`. For production set `NODE_ENV=production`, `HR_USERNAME`, `HR_PASSWORD`, use HTTPS, a private network or stronger identity-aware access control, and managed secret storage. Login uses an HTTP-only session cookie (8-hour expiry) and basic rate limiting, but is not an enterprise identity system. Sessions reset when the backend restarts. Do not publicly expose without HR approval and appropriate controls.

## Notes

- The approved subject for October 29 is `Daily Work Report - 29/10/2026`. `daily work report - 29/10/2026` works too. A wrong date or unrelated subject does not count.
- Employee reports can contain plain text or simple HTML; rich attachments are **not** rendered.
- The backend scans a bounded Gmail result set (up to 1,000 emails for a date search), then filters locally. For high-volume mailboxes, add a dedicated Gmail label or tighten search.
- Office hours are 9:30 AM–7:30 PM IST, but the report window is **9:30 AM to 11:59:59 PM IST** for the selected date. Midnight ends the previous day's report; messages from midnight to 9:29 AM do not count toward either day's report window. Half-day and late-evening emails count if received within the window.
- Gmail timestamps are shown in IST. Pending means **no matching report arrived for that chosen date**, not necessarily that the employee failed to work.
- The bottom **Full Report Reminder** button lists pending employees by their regular employee names. On click it **fetches fresh Gmail data first**, so anyone who has just submitted is removed. It opens WhatsApp with a predefined message. HR chooses the office group, adds mentions if desired, and manually sends. No phone numbers are needed; the button does **not** automatically send or tag members.
- The current roster uses the 17 supplied real sender addresses. Without Gmail authorization, no sample email matches this roster, so all 17 appear Pending in demo mode. This is **not** evidence that those people have failed to submit work.
